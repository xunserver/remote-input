- (direction) 采用富结构输入直接提炼，不追加需求访谈；以最终 PRD、技术附录、Architecture Spine 和仓库协作约束为输入。
- (decision) 来源路由：Architecture Spine 作为 adopted companion；PRD、技术附录和 AGENTS.md 完整吸收为 audit-only sources。原因是 PRD/附录保留了已关闭的待定项，AGENTS.md 描述的是待迁移 brownfield 边界，下游不能把它们与最终目标架构并列解释。
- (decision) Why：remote-copy 需要一条可替换的远程输入链路，使应用语义、协议关联、编码校验和链路可靠性各有唯一所有者；Browser 开发者应在自选 Transport 上获得稳定 Client，Server 与 Transport 实现者应独立复用 Session，并让连接恢复和失败语义在多种传输实现下保持一致。
- (capability) CAP-1 可组合的远程输入客户端 — Intent：Browser 调用者可使用自行选择的 Transport 建立远程会话、提交文本、查询 Operation、订阅状态与通知，并在显式关闭后再次连接。Success：在任一符合契约的 Client Transport 上，connect 仅在当前连接代的 session.open 成功后完成；未 ready 的业务调用确定性失败；disconnect 停止恢复且同一 Client 可再次 connect；SDK 不依赖具体 Transport。
- (capability) CAP-2 通用协议会话 — Intent：Browser 与 Server 可通过同一 Session 能力交换经校验的类型化请求、响应、入站请求、通知和心跳，且每次请求独立完成。Success：仅用完整消息 Transport 测试替身即可证明发送前登记关联、并发与逆序或早到响应不串配、响应期限从消息交付后独立计算、单次发送失败不影响其他请求、非法输入不进入 handler，释放后无 listener、pending 或 timer 遗留。
- (capability) CAP-3 完整消息可靠传输 — Intent：上层可并发发送和接收完整字节消息，并获得可靠、有序、保留边界且具有背压的双工交付。Success：契约测试证明空消息至最大消息均无部分、合并、重复或倒序上行交付；每个 send 只在对端确认整条消息后独立成功；容量受限时返回可识别失败；交付字节在回调后保持稳定。
- (capability) CAP-4 有界连接恢复与确定失败 — Intent：组合根可建立、观察、关闭和恢复传输连接，并为每次发送获得不会被后续恢复反转的确定本地结果。Success：连接代单调且快照无丢失；任一时刻至多一个连接或恢复过程；恢复和时限有界；显式关闭可取消恢复并允许后续重连；不可用期间新发送立即失败；失败区分 not-delivered 与 delivery-unknown 及调用级与连接代级影响；失败后不重放消息或泄漏资源。
- (capability) CAP-5 Socket.IO 双端互操作 — Intent：Socket.IO Client 与 accepted Server Socket 可作为同一完整消息 Transport 能力的双向互操作实现。Success：golden-wire 与故障注入测试证明大消息透明拆分和合法重组、连续消息保持边界与顺序、丢失重复乱序不会造成部分或重复交付、Transport ACK 与协议 Response 分离、新连接代隔离旧状态、Client 可主动恢复而 Server accepted Transport 不恢复已关闭 Socket。
- (capability) CAP-6 独立消费与协议治理 — Intent：Browser 与 Server 可只安装和版本化各自需要的 SDK、Session 与 Transport，同时共享唯一应用协议契约。Success：依赖图证明 Browser 不加载 Server runtime 或默认 Transport、Server 不依赖 SDK、协议类型与 schema 只定义一次、同 major 兼容性由 fixtures 保证；调用方、测试和中文文档原子迁移到新 API，旧 factory、alias、adapter 和双接口探测均不存在。
- (capability) CAP-7 长期 Operation 一致性 — Intent：调用者可提交、查询和持续观察长期远程输入 Operation，并在交付不确定或连接变化后避免陈旧状态回退和不安全重复执行。Success：inputText 在发送前创建或复用 operationId，ID 创建后的失败始终返回该 ID；同一 ID 可查询或显式重试；公共状态仅为 accepted、processing、succeeded、failed，权威缓存只接受严格更高且合法的 revision，terminal 不回退；ACK 与 Response 不冒充 Operation 完成；同一 Server 进程内重复 ID 保持幂等。
- (constraint) 必须保持 RemoteInputClient -> ProtocolSession -> MessageCodec -> MessageTransport 单向分层；应用语义、协议关联、编码校验和链路可靠性各有唯一所有者，不得引入跨层 Channel、重复队列或重复状态机。
- (constraint) SDK 接收调用方创建的 Transport 且不依赖具体实现；Browser 只消费 SDK 与选定的 Client Transport，Server 只消费 Session 与 Server Transport；Protocol、Session、Socket.IO Transport 与 SDK 独立消费和发布。
- (constraint) packages/protocol 是应用协议唯一事实源；所有入站字节必须经过运行时校验，禁止以类型断言绕过不可信输入边界。
- (constraint) Session 只依赖完整消息 send/receive 数据面且不读取或控制 Transport 生命周期；Client/Server 组合根编排生命周期，Transport 独占连接、恢复、排队、分片、ACK、重传和完整消息交付结果。
- (constraint) Transport 必须可靠、有序且保留完整消息边界；发送失败是本地最终态，失败消息不得跨 Connection Generation 重放；Transport ACK、协议 Response 与 Operation completion 是三种独立完成语义。
- (constraint) requestId、operationId、heartbeatId 与 Transport 序号是独立命名空间；跨层错误以稳定结构字段判别，明确区分 not-delivered 与 delivery-unknown，不依赖错误文本或跨包 instanceof。
- (constraint) Operation 公共状态只允许 accepted、processing、succeeded、failed；stage 承载下游阶段，权威通知携带递增 revision，SDK 只接受更高 revision 和合法迁移。
- (constraint) Session、Transport、SDK 和 Server 的队列、缓存、请求数与时间预算必须有界；failure、close 和 dispose 路径必须清除 listener、Promise、timer、队列和重组资源。
- (constraint) 当前拓扑保持 Browser 到单一 Node/Socket.IO Server，Server 同时托管静态资源；安全边界仅限受信任本机或 LAN，不构成公网安全方案；库默认不得记录 input text、协议 body 或 frame payload。
- (constraint) 采用严格 TypeScript 和判别联合；迁移是 private workspace 的原子 breaking change，不保留旧 API alias、adapter 或双接口探测，并同步更新 exports、测试、中文 README 与架构文档。
- (constraint) 自动真实联调只能发送 session.open，不得发送非空 input.submit；输入成功路径使用无 OS 副作用的 fake/direct handler。
- (constraint) 所有实现与验收必须服从 adopted Architecture Spine 的 AD-1 至 AD-18；精确接口、状态机、时限、资源上限、wire 格式、恢复策略和迁移顺序以该 companion 为准。
- (decision) Non-goal：本次不实现或模拟 Bluetooth/GATT/MTU、WebSocket 或其他 Transport，也不固定 Bluetooth 设备选择体验。
- (decision) Non-goal：不实现跨连接 Session resume、失败消息 replay、持久 delivery 或 exactly-once 业务执行。
- (decision) Non-goal：不实现认证、授权、TLS、端到端加密、公网部署防护、数据库、跨进程 Operation 持久化或多 Server 幂等域。
- (decision) Non-goal：不新增协议协商、压缩、在线 wire 参数协商或新的 wire major。
- (decision) Non-goal：不重设计 UI，不持久化输入历史，也不改变剪贴板、粘贴或其他下游输入执行能力。
- (decision) Non-goal：不提供公共 sendBatch，不向 Session 暴露 chunk/frame/window/ACK，不引入同时承担协议和传输职责的 Channel。
- (decision) Non-goal：本次不决定 registry、provenance、发布自动化或长期支持策略。
- (decision) Success signal：Browser 示例只创建并注入 Socket.IO Client Transport 后使用 SDK，Server 示例只组合 Server Transport 与 Session；关联、故障注入、恢复和资源清理测试无串配、部分、重复、乱序、失败后复活或泄漏；pnpm test:protocol、test:sdk、test:server、check 和 build 全部通过，exports、中文文档和实现一致，真实联调只执行 session.open。
- (note) 没有仍存活的假设或开放问题；PRD 中的 response timeout 假设及包名、接口名、lifecycle/error 待定项均已由 Architecture Spine 采纳并关闭。
